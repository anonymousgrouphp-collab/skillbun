# Static Assets & The Asset Pipeline in Phoenix

Static assets are integral to modern web applications, encompassing everything from images and fonts to stylesheets (CSS) and client-side scripts (JavaScript). In Elixir Phoenix applications, managing these assets efficiently is crucial for performance and developer experience. Phoenix provides a robust asset pipeline, leveraging `esbuild` as its default bundler, to streamline this process.

## 1. Understanding Static Assets

Static assets are files that are served directly by the web server without any dynamic processing by the application. They are typically stored in the `priv/static` directory in a Phoenix project.

*   **Examples**:
    *   Images (`.png`, `.jpg`, `.svg`)
    *   Fonts (`.woff`, `.ttf`)
    *   CSS files (`.css`)
    *   JavaScript files (`.js`)
    *   Favicon (`.ico`)

Phoenix uses `Plug.Static` to serve these files directly from `priv/static`, making it highly performant for fixed content.

## 2. The Phoenix Asset Pipeline with `esbuild`

The asset pipeline is a framework for managing and processing front-end assets. Phoenix 1.6+ integrates `esbuild` by default for bundling JavaScript and CSS, replacing previous tools like Webpack or Brunch.

### Why `esbuild`?
`esbuild` is an extremely fast JavaScript bundler and minifier. Its speed significantly improves development workflow by offering near-instantaneous rebuilds and quicker deployment times.

### How it Works:

1.  **Source Directory**: Your primary frontend source files reside in the `assets/` directory (e.g., `assets/js/app.js`, `assets/css/app.css`).
2.  **`esbuild` Configuration**: The `esbuild` setup is managed via `config/config.exs` and `config/dev.exs` which configure `esbuild` to compile these source files.
    *   In `config/dev.exs`, `esbuild` runs in watch mode for live reloading.
    *   In `config/runtime.exs` (or `config/prod.exs`), `esbuild` is configured for production builds, often triggered by `mix phx.digest`.
3.  **Compilation**: `esbuild` reads your `assets/` files, resolves dependencies (e.g., `@import` in CSS, `import` in JS), bundles them, and outputs the processed files into `priv/static/assets`.
4.  **Serving**: During development, Phoenix's dev server watches for changes. In production, `Plug.Static` serves these pre-compiled assets from `priv/static`.

### Key Files and Directories:

*   **`assets/`**: Contains raw JavaScript and CSS source files.
    *   `assets/js/app.js`: Your main JavaScript entry point.
    *   `assets/css/app.css`: Your main CSS entry point.
    *   `assets/package.json`: Manages frontend dependencies (e.g., `npx esbuild`).
*   **`priv/static/`**: The target directory where `esbuild` outputs compiled assets. This is what `Plug.Static` serves.
    *   `priv/static/assets/app.js`: Compiled JavaScript.
    *   `priv/static/assets/app.css`: Compiled CSS.
    *   `priv/static/assets/app.js.map`: Source map for debugging.
*   **`config/config.exs`**: General `esbuild` configuration.
*   **`config/dev.exs`**: Development-specific `esbuild` configuration (e.g., watch mode).
*   **`config/runtime.exs`**: Production-specific `esbuild` configuration and `mix phx.digest` settings.

## 3. Linking Assets in Templates

Phoenix provides helpers to link to your static and digested assets in your HTML templates.

*   **`~p` sigil**: Used for generating paths to routes, including static assets.
    ```elixir
    <link rel="stylesheet" href={~p"/assets/app.css"}>
    <script defer phx-track-static type="text/javascript" src={~p"/assets/app.js"}></script>
    <img src={~p"/images/logo.svg"} alt="Logo">
    ```
    When `mix phx.digest` is run, `~p` will automatically resolve to the digested asset path (e.g., `/assets/app-123456789.css`).

*   **`static_path/2` and `asset_path/2`**: While `~p` is the recommended way, these functions can also be used.
    *   `static_path(@conn, "/images/logo.svg")` -> `/images/logo.svg`
    *   `asset_path(@conn, "/assets/app.css")` -> `/assets/app-DIGEST.css` (in production after digest)

## 4. Deployment and Cache Busting

For production deployments, Phoenix employs cache busting to ensure users always receive the latest versions of your assets while leveraging browser caching for performance.

*   **Asset Digests**: The `mix phx.digest` task generates unique filenames (digests) for your compiled assets (e.g., `app-f09b23b1a8d0f1c2e3a4b5c6d7e8f90a.css`). This ensures that when an asset changes, its filename changes, forcing browsers to download the new version. Unchanged assets retain their digest and can be served from the cache.
*   **`priv/static/cache_manifest.json`**: This file, generated by `mix phx.digest`, maps original asset paths to their digested versions. Phoenix uses this manifest to serve the correct digested paths.
*   **Deployment Steps**: A typical production deployment workflow includes running `mix assets.deploy` (which executes `npm install`, `npx esbuild`, and `mix phx.digest`) before building and deploying the Elixir application.

## Code Example: `esbuild` Configuration in `config/config.exs`

```elixir
# In config/config.exs
config :my_app, MyAppWeb.Endpoint,
  # ... other endpoint config ...
  url: [host: "localhost"],
  # Serve static files from the priv/static directory.
  # The [file_system_purge: true] option is important for production to clear
  # stale assets generated by `mix phx.digest`.
  static_paths: ~w(priv/static),
  # ... other static config ...
  render_errors: [view: MyAppWeb.ErrorView, accepts: ~w(html json), layout: false],
  pubsub_server: MyApp.PubSub,
  live_view: [signing_salt: "YOUR_SIGNING_SALT_HERE"]

# Configures esbuild to bundle JavaScript and CSS.
config :esbuild,
  version: "0.17.11", # Or whatever version is current
  default: [
    args: ~w(js/app.js --bundle --target=es2017 --outdir=../priv/static/assets --external:/fonts/* --external:/images/*),
    cd: Path.expand("../assets", __DIR__),
    env: %{"NODE_PATH" => Path.expand("../deps", __DIR__)}
  ]

# In config/dev.exs for watch mode (example)
config :esbuild,
  version: "0.17.11",
  default: [
    args: ~w(js/app.js --bundle --target=es2017 --outdir=../priv/static/assets --external:/fonts/* --external:/images/* --watch), # Added --watch
    cd: Path.expand("../assets", __DIR__),
    env: %{"NODE_PATH" => Path.expand("../deps", __DIR__)}
  ]
```
Note: The `esbuild` args might vary slightly based on Phoenix version and project setup. The `external` flags tell `esbuild` not to bundle assets like fonts and images, which are handled directly by Phoenix's static file serving.
