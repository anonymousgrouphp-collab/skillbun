# SQL for Marketing Data Extraction: Study Guide

SQL (Structured Query Language) is an indispensable tool for Digital Marketing Analysts. It empowers you to directly interact with databases and data warehouses (like BigQuery or Snowflake) to extract, manipulate, and combine raw marketing data, transforming it into actionable insights. Mastering SQL allows you to move beyond pre-built reports, enabling deep-dive analysis, custom segmentations, and performance monitoring tailored to specific business questions.

## Core Concepts

### 1. Basic Data Retrieval: `SELECT` and `FROM`
These are the fundamental building blocks for querying data. `SELECT` specifies the columns you want to retrieve, and `FROM` specifies the table(s) you're pulling data from.

```sql
SELECT
    campaign_id,
    campaign_name,
    start_date,
    end_date
FROM
    marketing.campaigns;
```

### 2. Filtering Data: `WHERE`
The `WHERE` clause allows you to filter rows based on specified conditions. This is crucial for focusing on specific campaigns, date ranges, or performance metrics.

```sql
SELECT
    ad_id,
    ad_name,
    clicks,
    impressions
FROM
    marketing.ad_performance
WHERE
    campaign_id = 'CMP001'
    AND clicks > 100;
```

### 3. Aggregation and Grouping: `GROUP BY` and Aggregate Functions
Aggregate functions (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`) perform calculations on a set of rows and return a single value. `GROUP BY` organizes identical data into groups to perform aggregate functions on each group.

```sql
SELECT
    campaign_name,
    SUM(spend) AS total_spend,
    AVG(cpc) AS average_cpc
FROM
    marketing.campaign_daily_summary
WHERE
    report_date BETWEEN '2023-10-01' AND '2023-10-31'
GROUP BY
    campaign_name
HAVING
    SUM(spend) > 1000; -- HAVING filters groups after aggregation
```

### 4. Combining Data: `JOIN`
Relational databases often store related information in separate tables. `JOIN` clauses allow you to combine rows from two or more tables based on a related column between them.

-   **`INNER JOIN`**: Returns only the rows that have matching values in both tables.
-   **`LEFT JOIN` (or `LEFT OUTER JOIN`)**: Returns all rows from the left table, and the matching rows from the right table. If there's no match, `NULL` is returned for columns from the right table.
-   **`RIGHT JOIN` (or `RIGHT OUTER JOIN`)**: Returns all rows from the right table, and the matching rows from the left table. If there's no match, `NULL` is returned for columns from the left table.

```sql
SELECT
    mc.campaign_name,
    aps.clicks,
    aps.conversions,
    cd.demographic_segment
FROM
    marketing.campaigns AS mc
INNER JOIN
    marketing.ad_performance_summary AS aps ON mc.campaign_id = aps.campaign_id
LEFT JOIN
    marketing.customer_demographics AS cd ON aps.customer_id = cd.customer_id
WHERE
    mc.start_date >= '2023-01-01';
```

## Practical Application Example

Let's say you want to find the total revenue generated by each marketing channel for active campaigns in the last quarter, along with the average customer age for those conversions.

```sql
SELECT
    mc.marketing_channel,
    SUM(op.order_total) AS total_revenue,
    AVG(DATEDIFF(CURRENT_DATE(), c.date_of_birth) / 365) AS average_customer_age_at_conversion
FROM
    marketing.campaigns AS mc
INNER JOIN
    marketing.conversions AS conv ON mc.campaign_id = conv.campaign_id
INNER JOIN
    sales.orders AS op ON conv.order_id = op.order_id
INNER JOIN
    customers.customer_details AS c ON op.customer_id = c.customer_id
WHERE
    mc.campaign_status = 'active'
    AND conv.conversion_date BETWEEN '2023-10-01' AND '2023-12-31'
GROUP BY
    mc.marketing_channel
HAVING
    SUM(op.order_total) > 5000
ORDER BY
    total_revenue DESC;
```
