# Basic Interfacing & Communication Protocols

## Introduction
Embedded systems frequently need to communicate with various peripheral devices like sensors, actuators, memory, and other microcontrollers. To facilitate this, standardized communication protocols are used, each optimized for different applications based on factors like speed, distance, number of devices, and complexity. This guide explores three fundamental serial communication protocols: Universal Asynchronous Receiver-Transmitter (UART/USART), Serial Peripheral Interface (SPI), and Inter-Integrated Circuit (I2C).

## 1. Universal Asynchronous Receiver-Transmitter (UART/USART)

### Principles
UART (Universal Asynchronous Receiver-Transmitter) is a hardware device used for asynchronous serial communication, meaning it doesn't require a shared clock signal between devices. USART (Universal Synchronous Asynchronous Receiver-Transmitter) is an enhanced version that supports both asynchronous and synchronous modes.

*   **Asynchronous:** No common clock line. Synchronization is achieved using start and stop bits and agreeing on a fixed data rate (baud rate).
*   **Full-Duplex:** Capable of transmitting and receiving data simultaneously.
*   **Simple Wiring:** Typically uses two wires for communication:
    *   `TX` (Transmit): Output pin for sending data.
    *   `RX` (Receive): Input pin for receiving data.
*   **Baud Rate:** The rate at which information is transferred in a communication channel, measured in bits per second (bps). Both sender and receiver must operate at the same baud rate.

### Data Format
A typical UART data frame includes:
*   **Start Bit:** Always low (0), signals the beginning of data transmission.
*   **Data Bits:** 5-9 bits (commonly 8 bits) representing the actual data.
*   **Parity Bit (Optional):** Used for error checking. Can be even, odd, mark, or space parity.
*   **Stop Bit(s):** 1, 1.5, or 2 bits (always high/1), signals the end of the data frame.

```
       Start Bit   Data Bits (e.g., 8)  Parity (Optional)  Stop Bit
High --|___________|____________________|__________________|----------
Low  --|           |                    |                  |
```

### Timing and Applications
*   **Timing:** Baud rates must match. A small mismatch is tolerated, but significant differences lead to corrupted data.
*   **Applications:** Debugging consoles (e.g., via USB-to-UART bridge), GPS modules, Bluetooth modules, GSM/GPRS modems, communicating with other microcontrollers over short distances.

### Simple Configuration Example (Arduino - C++)
```cpp
void setup() {
  // Initialize serial communication at 9600 bits per second
  Serial.begin(9600); 
  // Wait for serial port to connect. Needed for native USB port only
  while (!Serial); 
  Serial.println("UART Communication Test");
}

void loop() {
  // Check if data is available to read
  if (Serial.available()) {
    char incomingByte = Serial.read(); // Read the incoming byte
    Serial.print("Received: ");
    Serial.println(incomingByte);
  }
  // Send data every second
  Serial.println("Hello from Arduino!");
  delay(1000); 
}
```

## 2. Serial Peripheral Interface (SPI)

### Principles
SPI is a synchronous serial communication interface used primarily for short-distance communication, especially in embedded systems. It operates in full-duplex mode and always involves a single master device and one or more slave devices.

*   **Synchronous:** Uses a shared clock line (`SCK`) for synchronization.
*   **Full-Duplex:** Data can be sent and received simultaneously.
*   **Multi-Slave Support:** Multiple slave devices can share the same `MOSI`, `MISO`, and `SCK` lines. Each slave requires its own dedicated `SS`/`CS` line.

### Key Lines
*   `SCK` (Serial Clock): Generated by the master to synchronize data transfer.
*   `MOSI` (Master Out Slave In): Data line from master to slave.
*   `MISO` (Master In Slave Out): Data line from slave to master.
*   `SS` / `CS` (Slave Select / Chip Select): Active-low signal from master to select a specific slave.

### Data Format and Timing
Data is typically sent in 8-bit or 16-bit chunks. The master generates the clock and toggles the `SS` line for the desired slave. When a bit is transmitted by the master on `MOSI`, a bit is simultaneously received from the slave on `MISO`.

*   **Clock Polarity (CPOL) and Clock Phase (CPHA):** These two settings (modes 0, 1, 2, 3) define when data is sampled relative to the clock signal. Both master and slave must agree on the mode.
    *   **CPOL (Clock Polarity):** Defines the idle state of the clock (0 for low, 1 for high).
    *   **CPHA (Clock Phase):** Defines whether data is sampled on the first or second edge of the clock cycle.

### Applications
SD card readers, display controllers (LCD/OLED), external ADCs/DACs, flash memory, shift registers, Ethernet controllers.

## 3. Inter-Integrated Circuit (I2C)

### Principles
I2C (Inter-Integrated Circuit), also known as TWI (Two-Wire Interface), is a synchronous, multi-master, multi-slave serial communication bus. It is widely used for connecting low-speed peripherals over short distances.

*   **Synchronous:** Uses a shared clock line (`SCL`).
*   **Half-Duplex:** Data can be sent or received, but not simultaneously, over a single data line.
*   **Multi-Master/Multi-Slave:** Allows multiple masters and multiple slaves on the same bus.
*   **Addressing:** Each device on the I2C bus has a unique 7-bit (or 10-bit) address.

### Key Lines
*   `SDA` (Serial Data): Bi-directional data line.
*   `SCL` (Serial Clock): Clock line, typically generated by the master.

Both `SDA` and `SCL` lines require pull-up resistors to maintain a high state when idle, as devices only pull them low.

### Data Format and Timing
Communication begins with a START condition (SDA goes low while SCL is high), followed by the 7-bit slave address and a R/W (read/write) bit. The addressed slave responds with an ACK (acknowledge). Data bytes are then exchanged, each followed by an ACK from the receiver. Communication ends with a STOP condition (SDA goes high while SCL is high).

```
   Start  Addr + R/W  ACK  Data Byte  ACK  Data Byte  ACK  Stop
SCL -----|__|---------|__|----------|__|----------|__|----------
SDA ---|__|-----|__|---|______|----|______|----|______|---|__|-----
```

### Applications
EEPROMs, RTCs (Real-Time Clocks), accelerometers, gyroscopes, temperature sensors, display drivers (e.g., for OLEDs), pressure sensors.

## Comparison of Protocols

| Feature          | UART/USART                 | SPI                         | I2C (TWI)                     |
| :--------------- | :------------------------- | :-------------------------- | :---------------------------- |
| **Type**         | Asynchronous Serial        | Synchronous Serial          | Synchronous Serial            |
| **Wires**        | 2 (TX, RX)                 | 4 (SCK, MOSI, MISO, SS/CS)  | 2 (SDA, SCL) + Pull-ups       |
| **Speed**        | Medium (up to ~10 Mbps)    | High (up to ~100 Mbps)      | Low-Medium (up to ~5 Mbps)    |
| **Complexity**   | Low (point-to-point)       | Medium (multi-slave)        | Medium (multi-master/slave)   |
| **Master/Slave** | Point-to-point             | 1 Master, Multiple Slaves   | Multi-Master, Multi-Slave     |
| **Addressing**   | No                         | Via dedicated SS/CS line    | Yes (7-bit or 10-bit address) |
| **Duplex**       | Full-duplex                | Full-duplex                 | Half-duplex                   |
| **Use Cases**    | Debugging, BT, GPS, GSM    | SD cards, Displays, Flash   | Sensors, EEPROMs, RTCs        |
