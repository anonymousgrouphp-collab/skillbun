# Edge Computing & Data Pre-processing

## Introduction to Edge Computing

Edge computing is a distributed computing paradigm that brings computation and data storage closer to the data sources, such as IoT devices or local networks. Unlike traditional cloud computing, where data is sent to a centralized data center for processing, edge computing processes data locally, at the "edge" of the network. This approach significantly reduces latency, conserves bandwidth, and enhances data privacy, making it crucial for modern embedded and IoT applications requiring real-time insights and responses.

## Core Concepts of Edge Computing

1.  **Local Data Processing:**
    *   **Description:** Data generated by sensors and devices is processed directly on the edge device itself or on a nearby local gateway (e.g., a mini-server or a more powerful embedded system). This prevents the need to transmit raw, unprocessed data over potentially long distances to a cloud server.
    *   **Benefits:** Enables quicker decision-making and reduces the computational load and storage requirements on central cloud infrastructure.

2.  **Data Filtering:**
    *   **Description:** Irrelevant, redundant, or noisy data is identified and discarded at the edge. This is essential for minimizing the data volume that needs to be transmitted and stored.
    *   **Techniques:** Thresholding (e.g., only send data if a value exceeds a limit), anomaly detection (filtering out unusual readings), and de-duplication.
    *   **Example:** A temperature sensor only reports data if the temperature changes by more than 0.5°C, or if it indicates an extreme condition.

3.  **Data Aggregation:**
    *   **Description:** Multiple data points are combined or summarized into a single, more concise piece of information before transmission. This transforms raw, voluminous data into meaningful summaries.
    *   **Techniques:** Calculating averages, sums, counts, minimums, maximums, or standard deviations over a defined time window or event series.
    *   **Example:** Instead of sending every individual light sensor reading, an edge device sends the average light intensity for the last five minutes.

4.  **Analytics on the Device or Local Gateway:**
    *   **Description:** Basic analytical tasks, ranging from simple rule-based logic to machine learning inference, are executed at the edge. This allows for immediate action or localized intelligence.
    *   **Benefits:** Critical for applications demanding real-time responses, such as predictive maintenance, security surveillance, and industrial automation.

5.  **Latency Reduction:**
    *   **Mechanism:** By performing computations close to the data source, the time taken for data to travel to a central server and back for processing and action is drastically cut.
    *   **Impact:** Essential for time-sensitive applications like autonomous vehicles, robotics, and augmented reality, where even milliseconds of delay can be critical.

6.  **Bandwidth Optimization:**
    *   **Mechanism:** Filtering and aggregating data locally reduces the sheer volume of data that needs to be transmitted over the network to the cloud.
    *   **Impact:** Lowers data transmission costs, particularly for deployments in remote areas with limited or expensive network connectivity, and eases congestion on network infrastructure.

7.  **Improved Privacy and Security:**
    *   **Mechanism:** Sensitive data can be processed, anonymized, or encrypted at the edge before any necessary insights are sent to the cloud. Raw, personal data may never leave the local environment.
    *   **Impact:** Reduces the attack surface for data breaches and helps organizations comply with stringent data privacy regulations (e.g., GDPR, HIPAA).

## Implementing Basic Machine Learning Inference at the Edge

Machine learning (ML) inference at the edge enables devices to make intelligent decisions locally without constant reliance on cloud connectivity. This involves deploying pre-trained, optimized ML models directly onto resource-constrained embedded systems.

**TensorFlow Lite for Microcontrollers (TFLite Micro):**

*   **Description:** TFLite Micro is an open-source library for deploying and running TensorFlow models on microcontrollers and other small, memory-constrained devices. It's designed for systems with as little as a few kilobytes of memory and no operating system.
*   **Key Features:**
    *   **Extremely Small Footprint:** Code size can be as small as 16KB, suitable for deeply embedded devices.
    *   **Bare-Metal Support:** Can run without an operating system, making it highly versatile for various microcontrollers.
    *   **Optimized for Efficiency:** Designed for low power consumption and fast inference on limited hardware.
    *   **Common Use Cases:** Keyword spotting (voice commands), gesture recognition, anomaly detection, and simple image classification.
*   **Typical Workflow:**
    1.  **Train Model:** Develop and train a neural network model using standard TensorFlow in Python.
    2.  **Convert to TensorFlow Lite:** Convert the trained model into the TensorFlow Lite format (`.tflite`).
    3.  **Quantize (Optional but Recommended):** Optimize the `.tflite` model for embedded devices, typically by reducing floating-point numbers to 8-bit integers (quantization), which significantly reduces model size and speeds up inference on integer-only hardware.
    4.  **Generate C Array:** Convert the `.tflite` model into a C source file containing the model data as a byte array.
    5.  **Integrate:** Include the TFLite Micro library and the generated model C array into your embedded C/C++ project. The TFLite Micro runtime handles loading and executing the model inference.

## Simple Edge Data Pre-processing Example (Conceptual C/C++)

Consider an environmental sensor array (e.g., temperature, humidity) on an IoT gateway. We want to process data at the edge to reduce cloud uploads.

```c
#include <stdio.h>
#include <stdbool.h>
#include <math.h>

// Configuration thresholds
#define TEMP_CHANGE_THRESHOLD 0.5f // Celsius
#define HUMID_CHANGE_THRESHOLD 2.0f // Percentage points
#define AGGREGATION_INTERVAL_SEC 300 // 5 minutes

// Global variables to maintain state
float last_reported_temp = NAN; // Use NAN for initial uninitialized state
float last_reported_humid = NAN;
long last_aggregation_timestamp = 0; // Simulate time in seconds

// --- Placeholder Functions (in a real system, these would interact with hardware/network) ---
float readTemperatureSensor() { return 22.5f + (float)(rand() % 100) / 100.0f; } // Simulate sensor reading
float readHumiditySensor() { return 55.0f + (float)(rand() % 100) / 100.0f; } // Simulate sensor reading
long getCurrentTimestamp() { static long t = 0; return ++t; } // Simulate increasing time
void sendToCloud(const char* dataType, float temp, float humid, long timestamp) {
    printf("[CLOUD SEND] Type: %s, Temp: %.2fC, Humid: %.2f%%, Time: %ld\n", dataType, temp, humid, timestamp);
}
// --- End Placeholder Functions ---

void processSensorReadings(float current_temp, float current_humid, long current_timestamp) {
    // Initialize last_reported values on first run
    if (isnan(last_reported_temp)) {
        last_reported_temp = current_temp;
        last_reported_humid = current_humid;
        last_aggregation_timestamp = current_timestamp; // Start aggregation timer
        printf("Initial readings set. Not sending to cloud yet.\n");
        return;
    }

    // 1. Data Filtering: Check for significant change in temperature or humidity
    bool temp_changed_significantly = fabs(current_temp - last_reported_temp) >= TEMP_CHANGE_THRESHOLD;
    bool humid_changed_significantly = fabs(current_humid - last_reported_humid) >= HUMID_CHANGE_THRESHOLD;

    if (temp_changed_significantly || humid_changed_significantly) {
        printf("Significant change detected. Sending alert/update to cloud.\n");
        sendToCloud("alert_change", current_temp, current_humid, current_timestamp);
        last_reported_temp = current_temp; // Update last reported values
        last_reported_humid = current_humid;
    } else {
        printf("No significant change. Data processed locally and discarded for cloud update.\n");
    }

    // 2. Data Aggregation: Periodically send aggregated data (e.g., last known values or averages)
    if (current_timestamp - last_aggregation_timestamp >= AGGREGATION_INTERVAL_SEC) {
        printf("Aggregation interval reached. Sending summary data to cloud.\n");
        // In a more complex scenario, you would have buffered readings to calculate averages
        sendToCloud("summary_interval", current_temp, current_humid, current_timestamp);
        last_aggregation_timestamp = current_timestamp; // Reset aggregation timer
        // Reset aggregation buffers here if calculating averages over the interval
    }
}

int main() {
    printf("Starting Edge Computing Data Pre-processing Simulation...\n");
    srand(1); // Seed for reproducible random numbers

    // Simulate readings over time
    for (int i = 0; i < 20; ++i) {
        printf("\n--- Time Step %d (Current Timestamp: %ld) ---\n", i + 1, getCurrentTimestamp());
        float temp = readTemperatureSensor();
        float humid = readHumiditySensor();
        long current_ts = getCurrentTimestamp();

        printf("Sensor Read: Temp=%.2fC, Humid=%.2f%%\n", temp, humid);
        processSensorReadings(temp, humid, current_ts);

        // In a real system, this would be a delay or other tasks.
        // Here, we manually advance time for the simulation.
        for (int j = 0; j < 50; ++j) { getCurrentTimestamp(); } // Simulate ~50 seconds passing
    }

    return 0;
}
```
*Note: This is a conceptual C/C++ example. In a real embedded system, `sendToCloud` would involve network protocols (MQTT, HTTP), `getCurrentTimestamp` would use a hardware timer, and `readSensor` would interact with actual sensor hardware.*
