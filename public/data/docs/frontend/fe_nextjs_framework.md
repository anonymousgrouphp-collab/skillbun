# Next.js: Full-Stack React Framework\n\nNext.js is a powerful, open-source React framework that enables developers to build production-grade, full-stack applications with an exceptional developer experience. It extends React's capabilities by providing solutions for server-side rendering (SSR), static site generation (SSG), Incremental Static Regeneration (ISR), file-based routing, and API routes out-of-the-box. This focus on performance, SEO, and developer productivity makes it a leading choice for modern web development.\n\n## 1. File-Based Routing\n\nNext.js simplifies routing by using a file-system based router. Any file inside the `pages` directory automatically becomes a route. This eliminates the need for manual route configuration, making it intuitive and scalable.\n\n*   **Static Routes**: `pages/about.js` becomes `/about`. `pages/index.js` is the root route (`/`).\n*   **Dynamic Routes**: Use square brackets `[]` in the file name to create dynamic routes. For example, `pages/posts/[id].js` will match `/posts/1`, `/posts/hello-world`, etc. The dynamic segment (`id`) is accessible via `router.query` or `context.params` in data fetching functions.\n\n**Example: Basic Page and Navigation**\n```jsx\n// pages/about.js\nimport React from 'react';\n\nconst AboutPage = () => {\n  return (\n    <div>\n      <h1>About Us</h1>\n      <p>Learn more about our mission.</p>\n    </div>\n  );\n};\n\nexport default AboutPage;\n\n// pages/index.js\nimport Link from 'next/link';\n\nconst HomePage = () => {\n  return (\n    <div>\n      <h1>Welcome to Next.js!</h1>\n      <p>Discover the power of full-stack React.</p>\n      <Link href="/about">\n        <a>Go to About Us</a>\n      </Link>\n    </div>\n  );\n};\n\nexport default HomePage;\n```\n\n## 2. Data Fetching Strategies\n\nNext.js offers several data fetching strategies, allowing you to choose the best approach for different use cases.\n\n### 2.1. Server-Side Rendering (SSR)\n\nSSR pre-renders a page on the server for each request. This means the HTML is generated on the server and sent to the client, which is excellent for SEO and dynamic content that changes frequently.\n\n*   **When to use**: Highly dynamic data, user-specific content, SEO-critical pages where content needs to be fresh on every request.\n*   **Function**: `getServerSideProps` is an asynchronous function exported from a page component. It runs exclusively on the server.\n\n**Example: SSR with `getServerSideProps`**\n```jsx\n// pages/products/[id].js\nimport React from 'react';\n\nconst ProductDetail = ({ product }) => {\n  if (!product) return <div>Product not found or loading...</div>;\n  return (\n    <div>\n      <h1>{product.name}</h1>\n      <p>{product.description}</p>\n      <p>Price: ${product.price}</p>\n    </div>\n  );\n};\n\nexport async function getServerSideProps(context) {\n  const { id } = context.params;\n  const res = await fetch(`https://api.example.com/products/${id}`);\n  const product = await res.json();\n\n  if (!product || Object.keys(product).length === 0) {\n    return { notFound: true };\n  }\n\n  return { props: { product } };\n}\n\nexport default ProductDetail;\n```\n\n### 2.2. Static Site Generation (SSG)\n\nSSG pre-renders pages at *build time*. The HTML and JSON data are generated once and served from a CDN, resulting in extremely fast page loads and reduced server load.\n\n*   **When to use**: Marketing pages, blog posts, documentation, e-commerce product listings (for stable data) where content doesn't change frequently.\n*   **Functions**: `getStaticProps` (fetches data for the page) and, for dynamic routes, `getStaticPaths` (defines which paths should be pre-rendered).\n\n**Example: SSG with `getStaticProps`**\n```jsx\n// pages/blog.js\nimport React from 'react';\n\nconst BlogPage = ({ posts }) => {\n  return (\n    <div>\n      <h1>Our Blog</h1>\n      <ul>\n        {posts.map((post) => (\n          <li key={post.id}>{post.title}</li>\n        ))}\n      </ul>\n    </div>\n  );\n};\n\nexport async function getStaticProps() {\n  // Data fetched at build time\n  const res = await fetch('https://api.example.com/blog-posts');\n  const posts = await res.json();\n\n  return { props: { posts } };\n}\n\nexport default BlogPage;\n```\n\n### 2.3. Incremental Static Regeneration (ISR)\n\nISR combines the benefits of SSG with dynamic updates. It allows you to re-generate static pages *after* your application has been built and deployed, without requiring a full redeployment.\n\n*   **When to use**: Content that updates periodically (e.g., news articles, popular product lists) but doesn't need to be fresh on every request.\n*   **Function**: Use `getStaticProps` with a `revalidate` property (in seconds) in the returned object.\n\n**Example: ISR with `revalidate`**\n```jsx\n// pages/products/[id].js (using ISR for product detail)\nimport React from 'react';\n\nconst ProductDetailISR = ({ product }) => {\n  return (\n    <div>\n      <h1>{product.name}</h1>\n      <p>Last updated: {new Date().toLocaleString()}</p>\n      <p>{product.description}</p>\n    </div>\n  );\n};\n\nexport async function getStaticPaths() {\n  // Fetch all product IDs to pre-render\n  const res = await fetch('https://api.example.com/products');\n  const products = await res.json();\n\n  const paths = products.map((product) => ({\n    params: { id: product.id.toString() },\n  }));\n\n  return { paths, fallback: 'blocking' }; // 'blocking' shows a loading state/SSR new paths\n}\n\nexport async function getStaticProps({ params }) {\n  const res = await fetch(`https://api.example.com/products/${params.id}`);\n  const product = await res.json();\n\n  if (!product || Object.keys(product).length === 0) {\n    return { notFound: true };\n  }\n\n  return {\n    props: { product },\n    revalidate: 10, // Re-generate this page (if requested) at most once every 10 seconds\n  };\n}\n\nexport default ProductDetailISR;\n```\n\n## 3. API Routes\n\nNext.js API Routes provide a simple solution to build your own API endpoints with Node.js, directly within your Next.js project. Files inside the `pages/api` directory are treated as API endpoints instead of pages, making Next.js a true full-stack framework.\n\n*   **Location**: Any file inside `pages/api` (e.g., `pages/api/users.js` becomes `/api/users`).\n*   **Usage**: Ideal for handling form submissions, connecting to databases, or creating custom backend logic without needing a separate backend server.\n*   **Request/Response**: Each API route exports a default function that receives `req` (request) and `res` (response) objects, similar to Express.js.\n\n**Example: Simple API Route**\n```jsx\n// pages/api/greeting.js\nexport default function handler(req, res) {\n  if (req.method === 'GET') {\n    res.status(200).json({ message: 'Hello from your Next.js API!' });\n  } else {\n    res.setHeader('Allow', ['GET']);\n    res.status(405).end(`Method ${req.method} Not Allowed`);\n  }\n}\n\n// pages/api/submit-data.js (Example for POST)\nexport default async function handler(req, res) {\n  if (req.method === 'POST') {\n    const { name, email } = req.body;\n    // In a real application, you would save this data to a database\n    console.log('Received data:', { name, email });\n    res.status(201).json({ message: 'Data received successfully!', name, email });\n  } else {\n    res.setHeader('Allow', ['POST']);\n    res.status(405).end(`Method ${req.method} Not Allowed`);\n  }\n}\n```\n\n## Checklist / Exercise\n\n1.  **Routing & Linking**: Create a new page `pages/dashboard.js` and a dynamic route `pages/users/[userId].js`.
